# Дельта спецификации

## Purpose

Определяет, как тестируется поведение сервиса: какие проверки должны существовать, на каком уровне они выполняются и что считается пригодным для развёртывания.

## ADDED Requirements

### Requirement: Поведение проверяется автоматическими тестами
Каждое требование из этих спецификаций SHALL быть покрыто автоматическим тестом, который выполняется без обращения к живому сервису и без сетевых вызовов во внешние системы. Тесты SHALL выполняться одной командой из чистой копии репозитория.

#### Scenario: Тесты запускаются в чистой копии
- **WHEN** выполняется команда запуска тестов в чистой копии репозитория с установленными зависимостями для разработки
- **THEN** тесты выполняются без ручной подготовки и без доступа к сети
- **AND** команда завершается с признаком успеха

#### Scenario: Проверка не покрыта тестом
- **WHEN** требование добавлено в спецификации, но соответствующий тест не написан
- **THEN** набор тестов не считается покрывающим спецификации

### Requirement: Внешние сервисы в тестах подменяются
Тесты SHALL перехватывать обращения к внешним сервисам и подставлять управляемый ответ, чтобы проверка не зависела от доступности и стоимости внешних сервисов и не расходовала их квоту.

#### Scenario: Внешний сервис отвечает ошибкой
- **WHEN** тест задаёт подставной ответ внешнего сервиса с ошибкой
- **THEN** сервис отдаёт код ответа, соответствующий этой ошибке
- **AND** реальный внешний сервис не вызывается

#### Scenario: Внешний сервис недоступен
- **WHEN** тест имитирует недоступность внешнего сервиса
- **THEN** сервис отдаёт код ответа, соответствующий недоступности
- **AND** тест завершается предсказуемо и быстро

### Requirement: Проверка ключа покрыта отдельно от проверки функциональности
Тесты SHALL отдельно проверять, что форвардящий эндпойнт отклоняет запрос без ключа и с неверным ключом, до того как запрос будет перенаправлен, и отдельно — что запрос с верным ключом обрабатывается.

#### Scenario: Запрос без ключа
- **WHEN** тест вызывает форвардящий эндпойнт без заголовка `X-API-Key`
- **THEN** сервис отвечает отказом в аутентификации
- **AND** обращения к внешнему сервису не было

#### Scenario: Запрос с неверным ключом
- **WHEN** тест вызывает форвардящий эндпойнт с ключом, не совпадающим с настроенным
- **THEN** сервис отвечает отказом в аутентификации
- **AND** обращения к внешнему сервису не было

#### Scenario: Запрос с верным ключом
- **WHEN** тест вызывает форвардящий эндпойнт с настроенным ключом
- **THEN** запрос обрабатывается и обращение к внешнему сервису состоялось

### Requirement: Секреты не попадают в тесты и в вывод
Тесты SHALL использовать подставные значения вместо реальных секретов, и выводимый ими текст SHALL NOT содержать значения учётных данных, независимо от verbosity.

#### Scenario: Тест использует подставной ключ
- **WHEN** тест проверяет аутентификацию
- **THEN** используется подставное значение, а не значение из окружения или из файла секретов

#### Scenario: Ошибка журналируется
- **WHEN** тест вызывает сбой, в котором участвуют учётные данные
- **THEN** в выводимых записях журнала нет значения учётных данных

### Requirement: Проверка перед развёртыванием запускается одной командой
Сервис SHALL предоставлять запускаемую проверку, которая проходит по всем проверяемым поверхностям развёрнутого сервиса и завершается с признаком успеха только тогда, когда все проверки пройдены. Проверка SHALL NOT содержать секретов и SHALL читать их из окружения или из неотслеживаемого файла.

#### Scenario: Проверка проходит
- **WHEN** запускается проверка против работающего сервиса, у которого все поверхности исправны
- **THEN** каждая проверка отмечена как пройденная
- **AND** проверка завершается с признаком успеха

#### Scenario: Проверка находит неисправность
- **WHEN** запускается проверка против сервиса, у которого форвардящий эндпойнт отвечает не так, как ожидается
- **THEN** неуспешная проверка отмечена как не пройденная с указанием ожидаемого и фактического результата
- **AND** проверка завершается с признаком неуспеха

#### Scenario: Секрет не хранится в проверке
- **WHEN** проверка читается как текст
- **THEN** в ней нет значения API-ключа
- **AND** ключ передаётся через окружение или неотслеживаемый файл
