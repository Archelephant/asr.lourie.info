# Дельта спецификации

## Purpose

Определяет, как сервис проверяет собственную конфигурацию при старте, как сообщает о готовности принимать трафик и что ему разрешено писать в журналы.

## ADDED Requirements

### Requirement: При старте проверяется обязательная конфигурация
Сервис SHALL при старте проверять наличие всех необходимых значений конфигурации и SHALL называть каждое отсутствующее значение, а не обнаруживать его отсутствие на первом же запросе.

#### Scenario: Отсутствует необходимое значение
- **WHEN** сервис стартует без необходимого значения конфигурации
- **THEN** при старте сообщается, что отсутствует именно это значение
- **AND** это отсутствие видно в журнале старта

#### Scenario: Все необходимые значения на месте
- **WHEN** сервис стартует, и все необходимые значения конфигурации на месте
- **THEN** при старте не сообщается об отсутствующей конфигурации

### Requirement: При старте различается сбой конфигурации и сбой зависимости
Сервис SHALL считать некорректную или отсутствующую конфигурацию фатальным условием старта, а недостижимую зависимость — условием деградации, не препятствующим старту.

#### Scenario: Отсутствуют учётные данные GigaChat
- **WHEN** сервис стартует без учётных данных GigaChat
- **THEN** сервис не стартует и называет отсутствующие учётные данные в своём журнале

#### Scenario: GigaChat недостижим
- **WHEN** сервис стартует с корректными учётными данными, но сервис GigaChat недостижим
- **THEN** сервис стартует
- **AND** сервис сообщает о недостижимости
- **AND** запросы, зависящие от GigaChat, сообщают, что он недоступен

### Requirement: Живость и готовность сообщаются раздельно
Сервис SHALL предоставлять сигнал живости, сообщающий только о том, работает ли процесс, и отдельный сигнал готовности, сообщающий, пригодны ли зависимости, необходимые для обслуживания запросов.

#### Scenario: Проверка живости при неработающей зависимости
- **WHEN** запрашивается конечная точка живости, пока вышестоящий сервис распознавания речи недостижим
- **THEN** конечная точка живости сообщает, что сервис жив

#### Scenario: Проверка готовности при неработающей зависимости
- **WHEN** запрашивается конечная точка готовности, пока вышестоящий сервис распознавания речи недостижим
- **THEN** конечная точка готовности сообщает, что сервис не готов
- **AND** называет недостижимую зависимость

#### Scenario: Проверка готовности при исправных зависимостях
- **WHEN** запрашивается конечная точка готовности, пока вышестоящий сервис распознавания речи достижим и учётные данные принимаются
- **THEN** конечная точка готовности сообщает, что сервис готов

### Requirement: Содержимое пользователей журналируется по настройке
Сервис SHALL записывать отправленные ответы анкеты, содержимое загруженных файлов, сгенерированные промпты и ответы языковой модели в свои журналы, когда подробное журналирование включено, и SHALL NOT записывать их, когда оно выключено. Подробное журналирование SHALL быть включено по умолчанию, чтобы содержимое сохранялось для последующего анализа; выключается оно явно.

#### Scenario: Отправка при включённом подробном журналировании
- **WHEN** посетитель отправляет анкету и подробное журналирование включено
- **THEN** журналы содержат отправленные ответы, сгенерированный промпт и ответ модели

#### Scenario: Отправка при выключенном подробном журналировании
- **WHEN** посетитель отправляет анкету и подробное журналирование выключено
- **THEN** журналы не содержат ни отправленных ответов, ни сгенерированного промпта, ни ответа модели

#### Scenario: Значение по умолчанию
- **WHEN** настройка подробного журналирования не задана в окружении
- **THEN** подробное журналирование считается включённым

#### Scenario: Операционное журналирование не затрагивается
- **WHEN** сервис обрабатывает запросы при любом значении настройки
- **THEN** журналы по-прежнему фиксируют метод, путь, статус и длительность каждого запроса

### Requirement: Учётные данные не попадают в журналы
Сервис SHALL NOT записывать в свои журналы настроенный API-ключ, учётные данные GigaChat или любые иные учётные данные.

#### Scenario: Учётные данные разбираются при старте
- **WHEN** сервис разбирает учётные данные во время проверки при старте
- **THEN** ни одна запись журнала не содержит значения учётных данных

#### Scenario: Запрос аутентифицируется
- **WHEN** запрос аутентифицируется или отклоняется из-за неверного ключа
- **THEN** ни одна запись журнала не содержит ни предъявленного, ни настроенного ключа

### Requirement: Каждая запись журнала появляется один раз
Сервис SHALL записывать каждую запись журнала ровно один раз, и не должен отдавать её одновременно собственным обработчиком логгера и обработчиком корневого логгера.

#### Scenario: Запись операционная
- **WHEN** сервис записывает операционную запись о запросе
- **THEN** она появляется в журнале один раз, а не дважды

#### Scenario: Источник значения разрешён
- **WHEN** сервис сообщает в журнале, откуда взято разрешённое значение
- **THEN** указан либо имя переменной, либо то, что взято встроенное значение по умолчанию, и никогда — «None»

### Requirement: Публичные элементы кода описаны
Каждый класс и каждая функция верхнего уровня SHALL сопровождаться описанием, объясняющим её назначение, а описание класса SHALL соответствовать его фактическому поведению.

#### Scenario: Класс без описания
- **WHEN** в коде появляется класс без описания
- **THEN** проверка это замечает

#### Scenario: Описание не соответствует поведению
- **WHEN** описание класса расходится с тем, что класс делает
- **THEN** проверка это замечает
